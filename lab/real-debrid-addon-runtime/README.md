# Real-Debrid addon runtime lab (experimental)

This isolated lab composes a new `ProviderManager` with `TorrentIndexerProvider` and, only when `enabled === true` plus a valid token are supplied, the opt-in Real-Debrid resolver chain. It does not alter the default bootstrap, public manifest, or public routes.

The versioned Compose file publishes no ports, runs as `1000:1000`, uses a read-only filesystem, drops all capabilities, has no Docker socket or persistent volume, and mounts an ephemeral token file read-only. The token is never an environment variable inside the container and must not be committed.

`tools/dry-run.ts` is intentionally offline: it always constructs the disabled composition and does not read the token file, perform DNS, fetch, or expose an addon endpoint. It is the only supported action for this milestone. A future separately authorized runtime execution must create a disposable secret file and override outside the repository, then validate an experimental manifest before any client installation.

The validated POSIX launcher is `scripts/dry-run.sh`. It rejects any supplied `REAL_DEBRID_TOKEN`, forces `REAL_DEBRID_ADDON_RUNTIME_ENABLED=false`, creates only an empty `0400` placeholder outside the repository, checks the rendered Compose JSON for published ports, performs one `compose run --rm --no-deps`, and always runs `compose down --remove-orphans`. It never prints the placeholder path or rendered environment. PowerShell equivalence is intentionally pending: Windows ACL-to-Linux UID semantics need a dedicated runtime validation.

The first Docker dry-run completed on runtime base `cf94968d6d7f641985e42bef6336408b63d4e907`: Compose rendered, the image built, the single run returned `DRY_RUN_OK` with exit code 0, no ports or external services were used, and `compose down` removed the residual project network and temporary placeholder.

No Stremio, Nuvio, playback, Docker runtime, or external service has been tested by this lab.

## Experimental HTTP runtime

`tools/http-server.ts` and the `addon-runtime-http-lab` Compose profile are a separate offline-only surface. Direct execution defaults to `127.0.0.1`; only the experimental Docker service binds internally to `0.0.0.0:7007`, so the disposable override can publish it exclusively as `127.0.0.1:<host-port>:7007`. The versioned Compose file still publishes no ports; `scripts/http-offline.sh` creates a disposable, mode-`600`, loopback-only override, validates it, retries health at most five times, and queries manifest and stream once each. It emits only `SERVICE_EXITED` or `HEALTH_TIMEOUT` when startup/readiness fails, without container logs. The default response is empty and no token, DNS, fetch, Real-Debrid, Stremio, Nuvio, or playback is used. The standard manifest, bootstrap, and router remain unchanged.

The first HTTP launcher runtime attempt on `8583d9ffb9b16ffff2a520368f1fe7a199321878` built and started the container, but all five health requests reset and ended with code `1`; cleanup left no container, network, or temporary file. No token or external service was used. The likely loopback-only internal bind is corrected offline; a new runtime validation remains pending.

The second attempt on `8453a649692ebb7305ed152e3ddf69e9a07e8921` also started the container but received connection resets until `HEALTH_TIMEOUT`, returned code `1`, and cleaned up completely. The command, environment names, internal port, and host publication are statically consistent, so the final cause is not yet confirmed. Fixed server markers and an allowlisted launcher report now distinguish missing/exited services, command/configuration mismatches, unconfirmed listen, connection reset, and health timeout without exposing raw logs or inspect data.

The latest runtime confirmed the container, process, command, internal port, loopback publication, startup, and listening state, but still ended in `HEALTH_TIMEOUT`. This narrows the unresolved boundary to the connection path after listen; it does not yet prove that Node accepted the request. Fixed markers now record request acceptance, health response start, response flush, and genuinely premature client aborts. Local HTTP/1.1 tests cover direct and keep-alive requests through both loopback and the container-style wildcard bind.

The following controlled run confirmed request acceptance plus health-response start and completion, while the launcher still returned `HEALTH_TIMEOUT`. The remaining defect was therefore isolated to the launcher client/validator boundary: it silently depended on a host `node` executable after a successful curl response. The launcher now uses one deterministic HTTP/1.1 curl function with explicit proxy bypass, separate mode-`600` header/body/metadata files, and JSON/schema validation inside the already-running tools container. Its allowlisted diagnostics report only curl category and presence/acceptance booleans. A replacement runtime validation is pending; no token or external service was used in this correction.

The replacement run on runtime base `b9c9be61b7dc29df8ff0418bfd43447b457107ab` completed successfully with exit code `0`. The loopback-only HTTP service started, health passed, the isolated experimental manifest was validated, and the offline stream route returned its valid response. Cleanup removed every container, project network, and temporary artifact. No token, Real-Debrid call, playback, Stremio, or Nuvio was involved. The standard bootstrap and addon remain unchanged; the next milestone is a temporary, explicitly authorized exposure of this experimental manifest to an authorized client.

## Temporary authorized client access

Phase 1—the isolated offline HTTP Docker validation—is complete. Client access remains a separate experimental phase.

`scripts/client-access.sh` is a separate, offline/fake-only launcher. It requires `EXPERIMENTAL_ADDON_CLIENT_ACCESS_AUTHORIZED=true`; no other truthy value is accepted. `LOOPBACK` is the default mode and binds only `127.0.0.1`. `LAN` additionally requires `EXPERIMENTAL_ADDON_LAN_ACCESS_AUTHORIZED=true`, an operator-supplied RFC1918 IPv4 address, and proof that the address belongs to an active local interface. It rejects wildcard, loopback, public, link-local, multicast, hostname and IPv6 LAN inputs. It publishes exactly one operator-selected, unoccupied host port in the inclusive range `1024..65535` to container port `7007`; it never selects another port automatically. An occupied port is rejected without stopping or modifying its existing process. It validates health, manifest and the offline stream response, and only then emits `CLIENT_ACCESS_READY`. The optional access timeout is an integer from `0` (unbounded until a handled signal) through `3600` seconds; larger values are rejected.

The launcher never enables Real-Debrid, never reads a token, and does not print a complete URL. The authorized operator can construct `http://<authorized-host>:<authorized-port>/manifest.json` locally from the values they supplied; the URL contains no credential. Loopback requires no firewall rule. LAN access may require a manual host firewall rule, but the launcher never changes iptables, nftables, UFW or any other firewall, and WAN forwarding is prohibited. This milestone adds no reverse proxy, public DNS or external tunnel. INT, TERM, TSTP and an optional bounded timeout trigger idempotent cleanup. Stremio, Nuvio and playback remain pending runtime validation.

## Experimental Real-Debrid client mode

`scripts/real-client-access.sh` is a separate runtime launcher. It requires exact `true` values for client access, Real-Debrid enablement and Real-Debrid authorization, plus a non-empty exact IMDb allowlist. The token is copied from an operator-supplied local file into an ephemeral `1000:1000`, mode `0400` secret mounted read-only; it is never supplied through Compose environment, a URL or the manifest. The normal HTTP runtime remains offline/fake and reads no token.

On runtime base `dd7c9a6`, a controlled LOOPBACK run published only `127.0.0.1:17007`, emitted `CLIENT_ACCESS_READY` and `REAL_DEBRID_MODE_ENABLED`, and validated `/health` plus the experimental `/manifest.json` with HTTP `200`. The token was provided only by file. `/stream` was not queried, the synthetic candidate was not sent to Real-Debrid, and manual `Ctrl+C` returned the expected code `130`. Cleanup removed every lab container, network, and temporary artifact without affecting existing Portainer containers. No reverse proxy, firewall change, WAN exposure, Stremio, Nuvio, or playback was used.

The next experiment is one explicitly authorized `/stream` query using a legal candidate only: an allowlisted IMDb ID, coherent real magnet and info hash, no discovery, no automatic repetition, and mandatory cleanup after the query. Stream validation, playback, Nuvio, and Stremio remain pending.
